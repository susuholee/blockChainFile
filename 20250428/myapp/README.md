# 아토믹 패턴을 활용해서 컴포넌트를 제어, css-in-javascript SPA, SSR에서 CSS 적용 방법
> 디자인 시스템의 효율을 높이기 위해서
> 2013년도 쯤에 `브래드 프로스트` 라는 개발자가 스타일 가이드 관련 경험도를 가지고 제시한 패턴
> 디자인적으로 사용자 인터페이스를 작고 작은 단위의 컴포넌트로 구분해서 유지보수를 효율적으로
관리하는 방법론

## 아토믹 패턴의 방식
> 아토믹 패턴의 방식은 자연에서 구성방식을 참고했다.
> 모든 물질이 원자부터 시작하는 것처럼
> 페이지의 디자인적인 요소를 원자, 분자 유기체 쭉쭉 형태를 점점 가지게 되는 UI적 요소를 표현했다.
> 페이지를 만들때도 연관이 있다. 원자부터 만들라는 철학적 의미가 담겨있다.

## 아토믹의 구성
1. 과한 컴포넌트의 분리는 오히려 프로젝트의 관리가 힘들어진다.
2. 작업자간에 소통이 되지않은 분리는 추구하면 안된다. (아토믹의 모든 원칙을 지키지 않고, 부분만 활용하는것도 방법)

*** 디자인 패턴의 주의점 ***
> 프로그래밍에서 디자인 패턴을 사용하는 이유? -> 기술 자랑?, X 스택 X, `저는 이 프로젝트에서 이런 화려하고 멋있는 디자인 패턴을 사용했습니다.` 왜 이 프로젝트에 이 디자인 패턴을 사용해야 했는지?
> `디자인 패턴`을 만든 목적은 이런 방식으로 개발을 많이 지향하다보니 좀더 효율적으로 프로젝트를
관리하고 유지보수성을 좋게 만들려고 반복하다보니, 즉 개발 방법론 목적에 맞게 작성했는가?


- 원자(Atoms) : 가장 작은 UI의 단위, 재사용이 되는 UI의 디자인을 띄고 있을때 만들면 된다. 버튼 즉, 더 쪼갤수 없는 UI의 단위를 표현할때
예 : label, input , button

- 분자(Molecules) : 두개의 원자 이상이 모여서 기능을 가지고 있는 컴포넌트 입력창 혹은 버튼과 라벨이 있는 검색 폼
예: 검색창

- 유기체(Organisms) : 여러 분자를 가지고 상위의 UI의 컴포넌트를 표현 (부모)

- 템플릿(templates) : 분자 또는 유기체를 배치해서 페이지의 구조를 표현한다. (동적인 컴포넌트의 내용은 여기서 처리)
(게시판의 글을 동적으로 만든다 가정하면 리스트가 분자로 표현되면 리스트를 동적으로 생성해주는 컴포넌트가 될것)

- 페이지(pages) : 템플릿을 가지고 와서 사용하는 페이지 UI를 표현하는 컴포넌트

```sh
src 
- components
-- atoms : 가장 작은 UI 단위
    -- button
        -- MainButton.js (메인페이지에서 사용되는 버튼)
        -- DetailButton.js (상세페이지에서 사용되는 버튼)
    -- input
        -- SearchInput.js
        -- MainSearchInput.js : 새로 만든 이유가 props를 너무 많이 전달해야하고, 구조가 복잡해진다 하면 새로운 컴포넌트를 작성
-- molecules
    -- searchBar
        -- SearchBar.js === MainButton.js + MainSearchInput.js
-- organisms : 분자 단위를 모아서 표현한 UI (헤더, 푸터, 사이드바)
    -- header
    -- sidebar
    -- footer

-- templates : 페이지의 동적인 내용을 가지고 있고, 레이아웃 구성을 하는 컴포넌트
    -- layout
        -- MainBoard.js (동적인 내용의 컴포넌트)
-- pages : 모든 요소를 가지고 완성된 페이지 전체의 컴포넌트
    -- Main.js
    -- detail.js
    -- ... 등등
```

## 원자 단위를 쪼갤때 재사용성을 보면서 버튼에 대한 크기가 각각 페이지에서 다르게 나온다면
- width : max-content
- padding으로 좌우를 밀어서 잡는다
